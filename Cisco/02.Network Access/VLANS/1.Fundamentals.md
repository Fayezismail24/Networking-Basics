# VLAN Fundamentals

## What is a VLAN?

A **Virtual Local Area Network (VLAN)** is a logical subdivision of a physical switch or switched network that allows you to group ports and create multiple independent broadcast domains on a single physical device.

### Without VLANs
```
Switch Port 1-48 (All in VLAN 1)
├─ PC1
├─ PC2
├─ Server
├─ Printer
└─ Phone

→ All devices in same broadcast domain
→ Broadcast storms affect all ports
→ No logical segregation
```

### With VLANs
```
VLAN 10 (Management)     VLAN 20 (Data)        VLAN 30 (Voice)
├─ Gi0/0/1 (PC1)         ├─ Gi0/0/11 (PC3)     ├─ Gi0/0/21 (Phone1)
└─ Gi0/0/2 (Mgmt PC)     ├─ Gi0/0/12 (PC4)     └─ Gi0/0/22 (Phone2)
                         └─ Gi0/0/13 (Server)

→ 3 independent broadcast domains
→ Data VLAN broadcast ≠ Voice VLAN broadcast
→ Requires Layer 3 routing between VLANs
```

## VLAN Types

### 1. **Data VLAN**
- Carries user data traffic
- Example: VLAN 20 for workstations, servers

### 2. **Management VLAN**
- Carries management traffic (SSH, Telnet, SNMP)
- Example: VLAN 10 for switch management IP
- **Best Practice**: Do NOT use VLAN 1 for management

### 3. **Native VLAN**
- Untagged VLAN on a trunk port
- Default is VLAN 1
- Frames **without 802.1Q tag** belong to native VLAN
- **Security Risk**: Mismatch can leak traffic between VLANs

### 4. **Voice VLAN** (Auxiliary VLAN)
- Carries VoIP traffic
- Example: VLAN 30 for IP phones
- Often configured with higher QoS priority
- Discovered via CDP (Cisco Discovery Protocol)

### 5. **Extended VLANs**
- VLAN IDs 1006–4094
- Require **VLAN Trunking Protocol (VTP)** in transparent mode or modern switches
- Not commonly used in small networks (CCNA scope: normal VLANs 1–1005)

---

## VLAN ID Range

| Range | Type | Notes |
|-------|------|-------|
| 1 | Default VLAN | Cannot be deleted; reserved |
| 2–1005 | Normal VLANs | Stored in `vlan.dat` |
| 1006–4094 | Extended VLANs | Stored in running-config (VTP transparent only) |

## 802.1Q Tagging (Frame Format)

When a port is a **trunk**, VLANs are distinguished using **802.1Q tags**—a 4-byte header inserted between the source MAC address and the EtherType field.

### Ethernet Frame with 802.1Q Tag

```
┌─────────────────────────────────────────────────────┐
│ Destination MAC (6 bytes)                           │
├─────────────────────────────────────────────────────┤
│ Source MAC (6 bytes)                                │
├─────────────────────────────────────────────────────┤
│ 802.1Q Tag (4 bytes)  ← NEW! Inserted here         │
│ ├─ TPID: 0x8100 (2 bytes) – Always 0x8100         │
│ └─ TCI (Tag Control Information, 2 bytes)          │
│    ├─ PCP (3 bits) – Priority (0–7)                │
│    ├─ CFI (1 bit) – Canonical Format Indicator (0) │
│    └─ VID (12 bits) – VLAN ID (0–4095)             │
├─────────────────────────────────────────────────────┤
│ EtherType (2 bytes) – IP=0x0800, ARP=0x0806, etc.  │
├─────────────────────────────────────────────────────┤
│ Payload (Data) + FCS                                │
└─────────────────────────────────────────────────────┘
```

### Example Tag Breakdown

**Hex: `0x8010`** (TPID + TCI for VLAN 16)

```
0x8100 (TPID) + 0x0010 (TCI)

TCI breakdown (0x0010):
├─ PCP: 000 (priority 0)
├─ CFI: 0 (canonical)
└─ VID: 0000010000 (binary) = 16 (decimal)
```

## Port Modes

### 1. **Access Port**
- Belongs to **ONE VLAN**
- Receives and sends **untagged frames**
- Default mode on most switches (but should be explicitly set)

```
Access Port (VLAN 20)
├─ Receives untagged frame
│  └─ Automatically assigns to VLAN 20
├─ Sends frame to VLAN 20 device
│  └─ Strips tag before transmission
└─ Does NOT forward tagged frames
```

**Config Example:**
```
interface GigabitEthernet0/0/5
  switchport mode access
  switchport access vlan 20
  exit
```

---

### 2. **Trunk Port**
- Carries **multiple VLANs**
- Receives and sends **tagged frames** (802.1Q)
- One **native VLAN** (untagged) for backward compatibility

```
Trunk Port (VLAN 1-4094)
├─ Receives tagged frame (e.g., VLAN 10, 20, 30)
│  └─ Forwards to corresponding VLAN
├─ Receives untagged frame
│  └─ Assigns to native VLAN (default VLAN 1)
└─ Sends all frames with tags (except native VLAN)
```

**Config Example:**
```
interface GigabitEthernet0/0/48
  switchport mode trunk
  switchport trunk native vlan 1
  switchport trunk allowed vlan 1,10,20,30
  exit
```

---

### 3. **Dynamic Desirable / Dynamic Auto** (DTP)

Switches can auto-negotiate trunk mode using **Dynamic Trunking Protocol (DTP)**.

| Mode | Initiates Trunk | Accepts Trunk Request | Outcome |
|------|-----------------|----------------------|---------|
| **on** | Yes | Yes | Always trunk |
| **desirable** | Yes | Yes | Trunk if neighbor agrees |
| **auto** | No | Yes | Trunk only if neighbor initiates |
| **off** | No | No | Always access |

**Default**: Many Catalyst switches default to `dynamic desirable` on newer IOS versions.

⚠️ **Security Risk**: DTP can allow unexpected trunking. Best practice: Disable DTP and explicitly set modes.

---

## Access vs. Trunk Comparison

| Feature | Access | Trunk |
|---------|--------|-------|
| **VLANs Carried** | 1 | Multiple (or all) |
| **Frame Tagging** | None (untagged) | 802.1Q tag |
| **Native VLAN** | N/A | Yes (untagged) |
| **Typical Use** | Host devices | Switch-to-switch, switch-to-router |
| **DTP Default** | `switchport mode access` (Catalyst) | Often `dynamic desirable` |

## Frame Flow Example

### Scenario: VLAN 20 PC sends ARP request

```
PC (VLAN 20, Gi0/0/12) → Switch (Access mode)

1. PC sends untagged ARP frame
2. Switch receives on Gi0/0/12 (access VLAN 20)
3. Switch forwards ARP to all other VLAN 20 ports
4. If trunk involved: tag added (0x8114 = VLAN 20)
5. Trunk carries tagged frame to other switch
6. Remote switch (access VLAN 20) strips tag
7. Frame delivered untagged to destination
```

### If Trunk Misconfigured

```
PC (VLAN 20) → Trunk (native VLAN 1) → Remote Access

1. ARP sent untagged from PC
2. Switch assigns to VLAN 20, forwards to trunk tagged
3. Trunk configured with native VLAN 1
4. Remote switch receives untagged (default native)
5. Frame ends up in VLAN 1, NOT VLAN 20
→ ARP request LOST
```

## VLAN Ranges in Memory

### VLAN 1–1005 (Normal Range)
- Stored in **VLAN database** (`vlan.dat` on flash)
- Requires **VTP** for synchronization across switches (if VTP enabled)
- Default for Catalyst switches

### VLAN 1006–4094 (Extended Range)
- Stored in **running-config** (not `vlan.dat`)
- Requires **VTP Transparent Mode** or **VTP disabled**
- Less common in CCNA labs (focus on 1–1005)

**Check Running Config:**
```
show running-config | include vlan
```

## Broadcast Domains & VLAN Boundaries

A **broadcast domain** is the set of all devices that receive a broadcast frame sent by any one device.

### Without VLANs (Single Broadcast Domain)
```
Broadcast from PC1 → All 48 ports receive it
```

### With VLANs (Multiple Broadcast Domains)
```
Broadcast from PC1 (VLAN 20) → Only VLAN 20 ports receive it
Broadcast from Phone (VLAN 30) → Only VLAN 30 ports receive it

To communicate across VLANs: Requires Layer 3 routing
```

## Key Exam Callouts

| Topic | Critical Point |
|-------|-----------------|
| **VLAN 1** | Default VLAN; cannot be deleted (even on extended switches) |
| **802.1Q TPID** | Always `0x8100`; identifies frame as tagged |
| **VID Field** | 12 bits = max 4096 VLANs (0–4095, but 0 and 4095 reserved) |
| **Native VLAN** | Frames without tag = native VLAN; mismatch = data loss |
| **Access Mode** | Receives/sends **untagged** only |
| **Trunk Mode** | Receives/sends **tagged** (+ native untagged) |
