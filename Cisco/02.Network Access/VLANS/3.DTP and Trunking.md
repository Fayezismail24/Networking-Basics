# Dynamic Trunking Protocol (DTP) & Trunking

---

## What is DTP?

**Dynamic Trunking Protocol (DTP)** is a Cisco proprietary protocol that allows switches to automatically negotiate trunk status on an interface. It uses frames sent on VLAN 1 to communicate mode preferences.

### Why DTP?
- Simplify trunk setup: no manual trunk mode required
- Auto-detection of switch-to-switch links
- **Backward compatibility** with older Catalyst switches

### ⚠️ Security Caveat
DTP is a **security liability** in production. Best practice: **Disable DTP and manually configure trunks**.

---

## DTP Modes

### 1. **On** (Unconditional Trunk)
- Always operates as a trunk
- Does NOT negotiate with DTP
- Forces trunk mode regardless of neighbor

```
Local: on
├─ Always trunk
├─ Ignores remote mode
└─ Works with: on, desirable, auto
```

**Configuration:**
```
Device(config-if)# switchport mode trunk
Device(config-if)# switchport nonegotiate
```

**Verification:**
```
Device# show interfaces GigabitEthernet0/0/48 switchport
Administrative Mode      : static access  ← Misleading; check "trunk"
Operational Mode         : trunk
Administrative Trunking  : enabled
```

---

### 2. **Off** (No Negotiation, Access Mode)
- Never trunks
- Disables DTP entirely
- Forces access mode

```
Local: off
├─ Never trunk
├─ Does NOT negotiate
└─ Ignores remote mode
```

**Configuration:**
```
Device(config-if)# switchport mode access
```

---

### 3. **Desirable** (Default on Many Catalyst)
- Actively negotiates trunk mode
- Sends DTP frames advertising trunk capability
- Becomes trunk if neighbor agrees
- Falls back to access if neighbor does NOT support DTP

```
Local: desirable
├─ Sends DTP "I want to trunk"
├─ Becomes trunk if neighbor = desirable, on, auto
└─ Becomes access if neighbor = off or no DTP response
```

**Configuration:**
```
Device(config-if)# switchport mode dynamic desirable
```

---

### 4. **Auto** (Passive Negotiation)
- Passively listens for DTP frames
- Does NOT initiate trunk negotiation
- Becomes trunk only if neighbor initiates (sends DTP)
- Default on many modern Catalyst switches

```
Local: auto
├─ Does NOT advertise trunk capability
├─ Becomes trunk if neighbor = desirable, on
└─ Becomes access if neighbor = off, auto
```

**Configuration:**
```
Device(config-if)# switchport mode dynamic auto
```

---

## DTP Negotiation Matrix

| Local \ Remote | on | desirable | auto | off |
|---|---|---|---|---|
| **on** | trunk | trunk | trunk | trunk |
| **desirable** | trunk | trunk | trunk | access |
| **auto** | trunk | trunk | access | access |
| **off** | off | off | off | off |

**Key Takeaway**: Only `auto` + `auto` results in access mode. All other combinations involving `on` or `desirable` result in trunk.

## Security Vulnerabilities of DTP

### Attack 1: VLAN Hopping via DTP

An attacker on an access port can trick the switch into trunking mode.

#### Scenario
```
┌─────────────────────────────┐
│ Cisco Switch (VLAN 20 - Data)│
├─────────────────────────────┤
│ Gi0/0/10: Access VLAN 20     │ ← Attacker here
│           (auto mode) DTP on │   (Attacker's laptop)
└─────────────────────────────┘

Attacker sends DTP frames (I want to trunk) → Switch agrees
Port becomes trunk → Attacker now sees traffic from ALL VLANs
```

#### Attack Flow
1. Attacker sends DTP "desirable" frames on access port
2. Switch in `auto` mode receives DTP
3. Switch agrees and converts port to trunk
4. Attacker creates 802.1Q tagged frames
5. Attacker accesses VLANs 10 (Management), 30 (Voice), etc.

---

### Attack 2: Native VLAN Hopping

Attacker sends untagged frames on trunk, targeting native VLAN.

#### Scenario
```
Switch trunk config:
├─ Native VLAN: 1 (untagged)
├─ Allowed VLANs: 1,10,20,30

Attacker sends:
├─ Untagged frame to default gateway
└─ Frame lands in VLAN 1 (management)
```

#### Mitigation
- Change native VLAN to unused VLAN (not VLAN 1)
- Example: `switchport trunk native vlan 999` (not used on any access port)

---

## Best Practice: Disable DTP

### On Access Ports
```
interface range GigabitEthernet0/0/1-47
  switchport mode access
  switchport nonegotiate  ← Disable DTP
  exit
```

### On Trunk Ports
```
interface GigabitEthernet0/0/48
  switchport mode trunk
  switchport nonegotiate  ← Disable DTP
  switchport trunk native vlan 999  ← Unused VLAN
  switchport trunk allowed vlan 1,10,20,30
  exit
```

### Verify DTP Disabled

```
Device# show dtp interface GigabitEthernet0/0/48

DTP is enabled globally and on this interface
DTP information for GigabitEthernet0/0/48:
  Sending DTP advertisements is off
  Requesting DTP to negotiate is off
  DTP cached vlan:
    NATIVE VLAN: none
```

## DTP Configuration Examples

### Example 1: Force All Ports to Explicit Mode

```
configure terminal

! Disable global DTP
no dtp advertise
no dtp require

! Disable DTP on all access ports
interface range GigabitEthernet0/0/1-47
  switchport mode access
  switchport nonegotiate
  exit

! Disable DTP on trunk
interface GigabitEthernet0/0/48
  switchport mode trunk
  switchport nonegotiate
  exit

exit
```

---

### Example 2: Enable DTP for Auto Trunk (Lab Only)

⚠️ **Not recommended for production**

```
configure terminal

interface GigabitEthernet0/0/48
  switchport mode dynamic desirable
  ! DTP enabled (default)
  exit

exit
```

### Verify Negotiation
```
Device# show interfaces GigabitEthernet0/0/48 switchport
Operational Mode         : trunk  ← DTP negotiated
Administrative Mode      : dynamic desirable
Administrative Trunking  : enabled
```

```
    VTP Operating Mode is TRANSPARENT
    Sending Pruning VLANs:
      Sending VLAN Info index 1
        Sending VLAN 1-4094
```

### Capture DTP Frames (Wireshark/Advanced)
DTP frames are sent as CDP-like advertisements on VLAN 1 at `01:00:0c:cc:cc:cc` MAC.

```
Frame: VLAN ID = 1 (native, untagged)
EtherType = 0x20AA (DTP)
```

## Cisco VLAN Trunking Protocol (VTP) vs DTP

| Feature | DTP | VTP |
|---------|-----|-----|
| **Purpose** | Auto trunk negotiation | Auto VLAN synchronization |
| **Frames** | Sent on access port (neighbor discovery) | Sent on trunk ports (VLAN database sync) |
| **Function** | Determines if port is trunk/access | Distributes VLAN database across switches |
| **Security** | VLAN hopping attack vector | VLAN database hijacking (deprecated) |
| **Modern Use** | Minimal (disabled best practice) | Deprecated in modern networks |

**Modern Approach**: Disable both DTP and VTP; use VLAN static config + VLAN APIs (Ansible, Terraform).

## Exam Callouts: DTP & Trunking

| Topic | Critical Point |
|-------|-----------------|
| **DTP Modes** | `on`, `off`, `desirable`, `auto` (4 options) |
| **auto + auto** | Results in ACCESS mode, not trunk |
| **desirable + auto** | Results in TRUNK mode |
| **on + anything** | Always trunk |
| **Native VLAN Mismatch** | Causes untagged traffic loss |
| **VLAN Hopping** | Via DTP negotiation or native VLAN attack |
| **Mitigation** | Disable DTP: `switchport nonegotiate` |
| **Native VLAN Best Practice** | Use unused VLAN (e.g., 999), not VLAN 1 |

## Practical Lab: Secure Trunk Setup

### Topology
```
Switch A              Switch B
(C3560-48)           (C3560-48)
Gi0/0/48 ↔ Gi0/0/48
(Trunk)      (Trunk)
```

### Switch A Configuration
```
configure terminal

! Create VLANs
vlan 10
  name Management
  exit

vlan 20
  name Data
  exit

! Access ports (secure)
interface range GigabitEthernet0/0/1-10
  switchport mode access
  switchport access vlan 10
  switchport nonegotiate
  description Access-Mgmt
  exit

interface range GigabitEthernet0/0/11-47
  switchport mode access
  switchport access vlan 20
  switchport nonegotiate
  description Access-Data
  exit

! Trunk (secure)
interface GigabitEthernet0/0/48
  switchport mode trunk
  switchport nonegotiate
  switchport trunk native vlan 999
  switchport trunk allowed vlan 1,10,20
  description Trunk-to-SwitchB
  exit

exit
```

### Verify on Both Switches
```
show vlan brief
show interfaces trunk
show interfaces GigabitEthernet0/0/48 switchport
show dtp interface GigabitEthernet0/0/48
```
