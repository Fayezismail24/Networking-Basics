# Inter-VLAN Routing

---

## The Problem: VLANs Isolate, But Users Need to Communicate

### Without Inter-VLAN Routing

```
VLAN 10 (Mgmt)           VLAN 20 (Data)
├─ Mgmt-PC 192.168.10.5  ├─ PC1 192.168.20.5
└─ Mgmt-PC 192.168.10.6  └─ Server 192.168.20.100

Switch learns MAC in VLAN 10 and VLAN 20 separately
Frame from VLAN 10 → cannot reach VLAN 20
→ No communication between VLANs (broadcast isolation works)
```

### With Inter-VLAN Routing (Layer 3)

```
PC1 (VLAN 20) → Server (VLAN 10)
1. PC1 (192.168.20.5) sends packet to Server (192.168.10.100)
2. PC1 is in different subnet → needs gateway
3. PC1 sends packet to default gateway (Layer 3 device)
4. Router/L3 switch receives packet, checks routing table
5. Finds route to 192.168.10.0/24 via VLAN 10
6. Replicates frame on VLAN 10 interface
7. Server receives packet
```

---

## Three Methods for Inter-VLAN Routing

### 1. Router-on-a-Stick (Legacy)
- Single router interface (subinterface per VLAN)
- One physical link to switch (trunk)
- Slower (all traffic goes through one link)

### 2. SVI (Switched Virtual Interface)
- Layer 3 switch with multiple SVIs (one per VLAN)
- Each SVI = VLAN interface with IP address
- Faster (traffic routed internally within switch)

### 3. Layer 3 Switching
- Modern: combine SVI + VLAN routing
- Multiple physical Gigabit uplinks per VLAN
- Highest performance

## Method 1: Router-on-a-Stick (Legacy but Still Used)

### Topology

```
┌─────────────────────────────┐
│ Catalyst 3560-48 (L2 Switch)│
├─────────────────────────────┤
│ VLAN 10 : Gi0/0/1-4 (access)│
│ VLAN 20 : Gi0/0/11-20 (access)
│ Gi0/0/48 : Trunk to Router  │
└─────────────────────────────┘
         │ Trunk (802.1Q)
         │ Gi0/0/48
         │
┌─────────────────────────────┐
│ Cisco 2911 Router           │
├─────────────────────────────┤
│ Gi0/0/1 : Trunk interface   │
│ ├─ Gi0/0/1.10 : VLAN 10     │
│ └─ Gi0/0/1.20 : VLAN 20     │
└─────────────────────────────┘
```

### Router Configuration

#### Step 1: Create Subinterfaces
```
configure terminal

! Physical interface
interface GigabitEthernet0/0/1
  no shutdown
  exit

! Subinterface for VLAN 10
interface GigabitEthernet0/0/1.10
  encapsulation dot1q 10
  ip address 192.168.10.1 255.255.255.0
  exit

! Subinterface for VLAN 20
interface GigabitEthernet0/0/1.20
  encapsulation dot1q 20
  ip address 192.168.20.1 255.255.255.0
  exit

exit
```

#### Step 2: Verify Subinterfaces
```
Router# show ip route
... 
C       192.168.10.0/24 is directly connected, GigabitEthernet0/0/1.10
C       192.168.20.0/24 is directly connected, GigabitEthernet0/0/1.20
```

#### Step 3: Verify Interface Status
```
Router# show interfaces GigabitEthernet0/0/1 | include up

GigabitEthernet0/0/1 is up, line protocol is up
GigabitEthernet0/0/1.10 is up, line protocol is up
GigabitEthernet0/0/1.20 is up, line protocol is up
```

### Switch Configuration

```
configure terminal

! Create VLANs
vlan 10
  name Management
  exit

vlan 20
  name Data
  exit

! Access ports
interface range GigabitEthernet0/0/1-4
  switchport mode access
  switchport access vlan 10
  exit

interface range GigabitEthernet0/0/11-20
  switchport mode access
  switchport access vlan 20
  exit

! Trunk to router
interface GigabitEthernet0/0/48
  switchport mode trunk
  switchport nonegotiate
  switchport trunk native vlan 999
  switchport trunk allowed vlan 1,10,20
  exit

exit
```

### Test Connectivity

```
VLAN 10 PC> ping 192.168.20.100 (VLAN 20)
✓ Success (packet routed through Gi0/0/1.20)

VLAN 20 Server> ping 192.168.10.5 (VLAN 10)
✓ Success (packet routed through Gi0/0/1.10)
```

### Limitations of Router-on-a-Stick
- Single point of failure (one physical link)
- All inter-VLAN traffic bottlenecked through router interface
- Latency higher than SVI routing
- Only 1 Gbps bandwidth (single Gigabit interface)

## Method 2: SVI (Switched Virtual Interface) Routing

### What is an SVI?

An **SVI** is a logical Layer 3 interface within a switch, associated with a VLAN. Each SVI can have an IP address and participate in routing.

### Topology

```
┌──────────────────────────────────┐
│ Catalyst 3560-48 (L3-capable)    │
├──────────────────────────────────┤
│ VLAN 10 (SVI) : 192.168.10.1/24  │
│   - Access ports: Gi0/0/1-4      │
│ VLAN 20 (SVI) : 192.168.20.1/24  │
│   - Access ports: Gi0/0/11-20    │
│                                  │
│ Routing enabled (IP routing on)  │
│ Switch routes between SVIs       │
└──────────────────────────────────┘
```

### Configuration

#### Step 1: Enable IP Routing on Switch

```
configure terminal

ip routing  ← This enables Layer 3 switching!

exit
```

#### Step 2: Create VLANs

```
configure terminal

vlan 10
  name Management
  exit

vlan 20
  name Data
  exit

exit
```

#### Step 3: Configure SVIs

```
configure terminal

interface Vlan10
  ip address 192.168.10.1 255.255.255.0
  no shutdown
  exit

interface Vlan20
  ip address 192.168.20.1 255.255.255.0
  no shutdown
  exit

exit
```

#### Step 4: Configure Access Ports

```
configure terminal

interface range GigabitEthernet0/0/1-4
  switchport mode access
  switchport access vlan 10
  exit

interface range GigabitEthernet0/0/11-20
  switchport mode access
  switchport access vlan 20
  exit

exit
```

### Verify SVIs and Routing

```
Switch# show ip route
Codes: C - connected, S - static, R - RIP, M - mobile...

Gateway of last resort is not set

C       192.168.10.0/24 is directly connected, Vlan10
C       192.168.20.0/24 is directly connected, Vlan20

Switch# show interfaces Vlan10
Vlan10 is up, line protocol is up
  Internet address is 192.168.10.1/24
  MTU 1500 bytes, BW 1000000 Kbit/sec...
```

### Test Connectivity

```
VLAN 10 PC (192.168.10.5)> ping 192.168.20.100 (VLAN 20)
Sending 5, 100-byte ICMP Echoes to 192.168.20.100
Success rate is 100%, round-trip min/avg/max = 1/2/4 ms

→ Much faster than router-on-a-stick!
```

## Advantages of SVI vs Router-on-a-Stick

| Feature | Router-on-Stick | SVI |
|---------|---|---|
| **Performance** | Slower (remote router) | Faster (local switching) |
| **Latency** | Higher | Lower (1-2ms vs 5-10ms) |
| **Equipment** | Switch + Router | L3 switch only |
| **Scalability** | Limited | Scales to many VLANs |
| **Bandwidth** | Single link (1 Gbps) | Multiple links possible |
| **Cost** | Higher (2 devices) | Lower (1 device) |

## Layer 3 Switch Configuration Comparison

### Scenario: 3-VLAN Setup on L3 Switch

#### VLAN 10 (Management)
- SVI IP: 192.168.10.1/24
- Access ports: Gi0/0/1-4
- Gateway for management devices

#### VLAN 20 (Data)
- SVI IP: 192.168.20.1/24
- Access ports: Gi0/0/11-20
- Gateway for workstations

#### VLAN 30 (Voice)
- SVI IP: 192.168.30.1/24
- Access ports: Gi0/0/21-30
- Gateway for IP phones

#### Full Configuration

```
configure terminal

! Enable Layer 3 routing
ip routing

! Create VLANs
vlan 10
  name Management
  exit

vlan 20
  name Data
  exit

vlan 30
  name Voice
  exit

! Configure SVIs
interface Vlan10
  ip address 192.168.10.1 255.255.255.0
  no shutdown
  exit

interface Vlan20
  ip address 192.168.20.1 255.255.255.0
  no shutdown
  exit

interface Vlan30
  ip address 192.168.30.1 255.255.255.0
  no shutdown
  exit

! Configure access ports
interface range GigabitEthernet0/0/1-4
  switchport mode access
  switchport access vlan 10
  description Management-Workstations
  exit

interface range GigabitEthernet0/0/11-20
  switchport mode access
  switchport access vlan 20
  description Data-Workstations
  exit

interface range GigabitEthernet0/0/21-30
  switchport mode access
  switchport access vlan 30
  description IP-Phones
  exit

exit
```

## Troubleshooting Inter-VLAN Routing

### Issue: Hosts Cannot Ping Between VLANs

#### Diagnostic Steps

```
! Step 1: Verify routing enabled
show ip routing

! Step 2: Check routing table
show ip route

! Step 3: Verify SVIs exist and are UP
show interfaces Vlan10 | include up

! Step 4: Verify VLAN membership
show vlan brief | include 10
show interfaces GigabitEthernet0/0/1 switchport

! Step 5: Test with extended ping
ping 192.168.20.100 source 192.168.10.1
```

### Common Issues

| Symptom | Cause | Fix |
|---------|-------|-----|
| SVIs down | `ip routing` not enabled | `ip routing` in global config |
| Hosts can't reach gateway | SVI IP not configured | Add IP to SVI interface |
| Routing works; firewall blocks | ACL on SVI | Remove or modify ACL |
| No inter-VLAN traffic | VLAN not created | `vlan 10`, etc. |

## Exam Callouts: Inter-VLAN Routing

| Topic | Critical Point |
|-------|-----------------|
| **Router-on-Stick** | Subinterface per VLAN (`Gi0/0/1.10`, `.20`, etc.) |
| **Encapsulation** | `encapsulation dot1q <vlan-id>` on router subif |
| **SVI** | Layer 3 switch SVI = `interface Vlan<id>` |
| **IP Routing** | Must enable `ip routing` on L3 switch |
| **Default Gateway** | Host default gateway = SVI address |
| **Performance** | SVI faster than router-on-stick (same device) |
